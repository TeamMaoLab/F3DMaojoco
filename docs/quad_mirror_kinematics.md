# 四足镜像腿运动学（核心踩坑记录）

记录 2026-07-17 把 LUT 单腿运动学扩展到 4 腿时，镜像腿处理的三层错误。
**这份文档存在的意义：每一个坑我都犯过错，下次再碰到不要再走一遍。**

## 结论先行

镜像腿（FL/RL）要正确运动，**必须同时做三件事**：

| 项 | 非镜像腿（FR/RR） | 镜像腿（FL/RL） |
|---|---|---|
| 腿根 Group 旋转 | 单位阵 | `Rx(π)` = 绕 X 翻 180°（diag(1,-1,-1)）|
| 关节角 | LUT 原值 θ | **-θ**（取负）|
| joint_anchor | LUT 原值 | **Z 分量取负**（[x,y,z] → [x,y,-z]）|

舵机（固定件）单独处理：直接用世界变换 `world_t_mm + world_rot` 挂 scene，**不算局部旋转**，不跟关节动。

## 数学推导（关键）

### 1. 关节角为什么要取负

数值证明（误差 0.0000）：

```
Rx(π) · Ry(θ) · Rx(π)⁻¹ = Ry(-θ)
```

含义：在已经被 Rx(π) 翻转的局部系里绕 Y 转 θ，在世界系看就是绕 Y 转 -θ。
所以镜像腿要让"世界系里的运动"和原版一致，局部必须转 -θ。

### 2. anchor 的 Z 为什么要取负

joint_anchor_mm 是相对腿根的关节位置（来自 leg_kinematic.json，原版腿）：
```
shin.anchor = [25, 0, -43.3]   # 大腿下方
```

镜像腿的腿根 Group 自带 Rx(π)，会把挂在它下面的所有局部坐标翻 Y/Z。
如果直接用原版 anchor，世界位置 = `Rx(π) · [25,0,-43.3] = [25,0,+43.3]`——**关节跑到头顶**。

修正：镜像腿用 anchor' = `[25, 0, +43.3]`（Z 取负）。
经 Rx(π) 翻转后世界位置 = `Rx(π) · [25,0,+43.3] = [25,0,-43.3]`，回到地面方向。✓

### 3. 完整变换链（最终验证）

镜像腿一个零件的完整世界变换 =
`坐标系 Rx(π)` × `局部 Ry(-θ)` × `STL 顶点反射 diag(1,1,-1)`

Fusion 导出镜像 occurrence 的 STL 时会把顶点 Z 取负（diag(1,1,-1) 反射）。
三层叠加：

```
diag(1,-1,-1) · Ry(-θ) · diag(1,1,-1)
= diag(1,-1,-1) · diag(1,1,-1) · Ry(θ)    （因为 Ry(-θ)·diag(1,1,-1) = diag(1,1,-1)·Ry(θ)）
= diag(1,-1,1) · Ry(θ)
```

`diag(1,-1,1)` = Y 反射。这正好是"原版腿 Ry(θ) 在 Y 方向反射"的完整表达。
即左右镜像完整成立，零件几何、关节位置、运动方向三者都对称。

## 我犯过的三个错误（按时间顺序）

### 错误 1：以为"不取负"

**错误推导**：用反射矩阵 M=diag(1,-1,1) 算共轭，得到 `M·Ry(θ)·M = Ry(θ)`，于是判断"镜像腿不取负"。

**错在哪**：occurrence 的镜像变换是**旋转** `Rx(π)=diag(1,-1,-1)`，不是**反射** `M=diag(1,-1,1)`。
这俩对 Ry 的共轭效果完全相反：
- `M·Ry(θ)·M = Ry(θ)`（反射不变）
- `Rx(π)·Ry(θ)·Rx(π)⁻¹ = Ry(-θ)`（旋转取负）

**教训**：数值验证永远比符号推导可靠。`Rx(π)·Ry(θ)·Rx(π)⁻¹` 直接算出 `Ry(-θ)`，误差 0.0000。

### 错误 2：只取负，没改 anchor

取负让世界旋转对了，但 anchor 还是原版的，关节位置在头顶。
症状：站姿下 FL/RL 的 shin 关节 Z=+39.4（飞到天上），零件跟着飞。

**教训**：镜像腿要改的不只是角度，还有 anchor。Rx(π) 会翻转所有局部坐标，anchor 也得对应翻转。

### 错误 3：相信图像分析工具

用 analyze_image MCP 看截图，它反复给出错误描述：
- 第一次："4 条腿对称、能站稳"（实际飞天）
- 第二次："只有 3 条腿"
- 第三次："蓝色 FL 飘在空中"（实际几何完全对称）

**真相来源**：直接读 Three.js 的顶点世界坐标（`localToWorld` 遍历 5916 个顶点），
FR 和 FL 的 shin 顶点 Z 范围完全一致（[-91.3, -32.6]）。

**教训**：图像分析不可信，几何数据（顶点世界坐标）才是真相。
自动化验证用 puppeteer 读 `Box3` 或顶点，不要用图像识别。

## 调试方法论（这次总结出来的）

修镜像腿问题的有效流程：

1. **数学推导**：写出完整变换链（坐标系 × 关节 × 顶点反射）
2. **数值验证**：node 里用纯 JS 复刻矩阵运算，对比预期
3. **浏览器读数**：puppeteer + `localToWorld` 读实际顶点世界坐标
4. **像素分析只作辅助**：颜色分类容易误判，不能作为通过/失败判据
